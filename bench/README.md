# Which models can actually drive this?

The README used to answer that with reasoning. This answers it with a number.

## What is measured

**Not** whether the model emits valid JSON. Constrained decoding guarantees that
at any size, and it was never the hard part. What is measured is:

1. **Verb choice** — given a request in English, does it pick the right one of 34?
2. **Arguments** — does it put the right values in the right keys?
3. **Read-back** — handed a result, does it act on what the result actually says,
   or on what it guessed before reading?

Read-back is the line between an assistant and a command parser, so it is scored
separately. Four of those tasks check a specific value lifted out of the result —
the slot the diamonds were actually in, the coordinates the search actually
returned — so a model that ignores the result and invents a plausible number
fails even when the verb is right.

## Running it

```bash
ollama pull qwen2.5:3b
python bench/run.py qwen2.5:3b                                  # flat schema
GHOST_SCHEMA=actions.v2.schema.json python bench/run.py qwen2.5:3b   # per-verb
```

No Minecraft required — it is text in, JSON out, scored against a fixed key.
`temperature 0` and a fixed seed, because a benchmark that changes between runs
cannot be checked by anyone else.

Every response is written to `results-<model>-<schema>.jsonl`, including the ones
that passed. **Read those before believing the table.** A summary nobody can
audit is a claim with better formatting.

## The task set

30 single-shot requests plus 4 read-back tasks, in `tasks.json`, grouped by the
tier the README used to claim could handle them. `accept` lists every verb a fair
reader would call correct, so a defensible alternative is not punished.

The set is small and hand-written. It is enough to falsify a wrong claim, which
is what it was built for; it is not enough to rank models finely, and nobody
should use it that way.

## Honest limits

- **Two models, one family.** Qwen2.5 at 3B and 7B. Nothing here says how Llama,
  Mistral or Phi behave, and the family may suit this task better or worse.
- **34 tasks.** One task is three percentage points. Treat single-task
  differences as noise.
- **Single-turn.** A real session recovers from a bad first action; this does not
  measure recovery.
- **The answer key is a judgement.** Where two verbs are genuinely defensible
  both are accepted, but somebody still drew that line.
- **CPU inference on a Ryzen 1600AF.** Speed numbers say nothing about the models
  and everything about the machine.

## What it found

Two things, and the second was the point.

**The old tier claims were wrong.** The README said a 1-3B model could handle
literal lookups — `say`, `where`, `read`, `find`, `have`, `places`, `worn`, `bag`.
Both models scored **0/8** on that tier against the shipped schema. The claim was
reasoned from what each step seemed to demand, never run, and stated with more
confidence than it had earned.

**Most of the failures were the schema's, not the model's.** The shipped schema
is a bare enum of 34 verb names and a flat bag of 31 optional properties, with
only `do` required. Nothing in it says which arguments belong to which verb.
So a model that understood the request perfectly still failed:

```
"Break the stone at 44 12 -8"  ->  {"do":"break","block":"[44, 12, -8]","face":"down"}
"Go to the garden"             ->  {"do":"goto","to":[2,64,3]}
```

Right verb, right values, wrong keys. `actions.v2.schema.json` binds arguments to
verbs — one `oneOf` branch per verb, `const` discriminator, its own properties,
`additionalProperties: false`, and a description of what the verb is for. The
wrong key stops being a mistake and becomes ungrammatical: the decoder cannot
emit it.

It is generated by `derive_v2.py` **by parsing Bridge.java**, not hand-written,
for the same reason `checkVerbs` exists — a hand-maintained table drifts, and the
drift stays invisible until someone benchmarks it.

`oneOf` rather than the more natural `if`/`then` because llama.cpp's
schema-to-GBNF converter, which Ollama uses, does not support `if`/`then`. It
would have silently produced a weaker grammar. Checked by running it, not by
reading the docs.
